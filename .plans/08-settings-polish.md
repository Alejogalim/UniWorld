# 08 — Settings (Design §7.5) + polish backlog

Read first: `.plans/A-build-conventions.md`, `DESIGN.md`, `Design.md` §5.1 and §7.5, `src/store/{settings,secrets,profile,tracked}.ts`, `src/app/theme.ts`, `src/ui/layout/LanguageSwitcher.tsx`.

## Settings (`src/ui/screens/Settings.tsx` + `src/ui/screens/settings/`)
One page (page wrapper `px-12`, max 1120px, sections separated by `Rule`, each section = Title + short line + controls; no cards).
- [x] 1. **Profile**: a compact read-only summary (name, primary language + other languages with levels, program, citizenship/residence if set, using `languageName`/`countryName` in the UI language) and a secondary "Edit profile" → `navigate('/onboarding', { state: { from: 'settings' } })`. In the onboarding Finish handler, if `location.state?.from === 'settings'` navigate back to `/settings` instead of `/counselor` (and the AI key step may be skipped: when editing, keys that are already stored show "Saved in your keychain" and Finish is enabled without re-entering them — check with `getSecret`).
- [x] 2. **Interface**: language `Select` (English / Español / Tiếng Việt; same behaviour as the rail switcher: changes i18n and saves `uiLang` on the profile) and theme `Select` (System / Light / Dark via `useTheme().setMode`).
- [x] 3. **AI providers**: for each of OpenRouter (required for the Finder) and OpenCode Go (optional, "Experimental" badge, Counselor only): status line ("Saved in your keychain" in evidence green / "Not set" chart-grey — use `getSecret` only to know presence; never display the key), a password `Input` to replace it, buttons "Save key" (primary for OpenRouter region only; secondary otherwise), "Test connection" (secondary; tests the stored key via `core.testConnection`), "Remove key" (quiet, inline confirm). Results inline (same styles as onboarding).
      **Model ID**: `Input` prefilled with `getSetting('model')`, placeholder = `DEFAULT_MODEL` from `@/core`; "Save" writes `setSetting('model', v)` (empty → `deleteSetting('model')` = default). **Counselor provider**: `Select` OpenRouter / OpenCode Go → `setSetting('default_provider', …)` (disable OpenCode option when no OpenCode key).
- [x] 4. **Your data**: "Clear all my data" (secondary with a destructive-looking signal outline is NOT allowed — use secondary + inline confirm panel: "This deletes your profile, chats, careers, searches, cached details, your university list and both AI keys from this computer." with a primary "Delete everything" and quiet "Cancel"). Implementation: one `getDb()` transaction-like sequence `DELETE FROM` counselor_message, career_path, counselor_session, uni_search, uni_detail_cache, tracked_uni, profile_language, profile, settings; `deleteSecret('openrouter')`, `deleteSecret('opencode')`; reset in-memory stores (profile → null, counselor/finder/tracked/onboarding-draft resets, theme → system); `i18n.changeLanguage('en')`; `navigate('/onboarding', { replace: true })`.
- [x] 5. **About**: one short paragraph: real data only (facts come from sources with quotes; missing facts say so), plus attributions with links opened via `openUrl`: ROR (CC0), Hipo university-domains-list (MIT), Natural Earth (public domain), and the app version from `@tauri-apps/api/app` `getVersion()` in mono.
- [x] 6. i18n: `settings` namespace (en/es/vi), registered in `src/i18n/index.ts` and `scripts/check-i18n.ts`.

## Polish backlog (from the orchestrator's visual review)
- [x] 7. **Onboarding layout**: the Back/Next row must sit directly under the step content (24px gap), not pinned to the bottom of the window. The shell title for the onboarding route should be "Your profile" (`common.screens.onboarding`, all 3 languages) so it doesn't repeat the sheet's "Welcome to UniWorld".
- [x] 8. **Finder rest layout**: two columns at rest — left column (≈420px): Careers, Scope (continent chips + "Whole world"), Filters, Search button, any key/no-career messages; right: the globe, as large as the remaining field allows (square, fits height `calc(100vh - header)`), with the scope chips under it. The searching layout (380px globe column + results) stays as is. Make sure nothing important is below the fold at 1200×800. Remove the globe's specular highlight (use a `MeshLambertMaterial`-like look: `globe.globeMaterial()` with `shininess = 0` and no specular, or swap to `new THREE.MeshLambertMaterial({ color })`).
- [x] 9. **Counselor careers**: show only the most recent batch of career ideas, plus a "Saved careers" sub-list of saved careers from earlier batches (deduplicated by title). On "Try again" after a failed `send`, don't add a second student bubble in the UI.
- [x] 10. **Detail page without route state**: look up name/city/country from `useTracked` by `rorId` before falling back to the rorId; never store the rorId as a name (disable "Add to my list" if no name is known, with a hint to open it from the Finder).
- [x] 11. **Empty and error states pass**: every screen has a designed empty state and every async action shows errors via `ErrorNote` with an action. Missing-key copy matches Design §5.1 everywhere: Finder → "University search needs an OpenRouter key (for verified web search)."; Counselor/detail → "Add an AI key in Settings." Check all three languages render without overflow (labels wrap).
- [x] 12. **Startup**: `initTheme()` must not block first render on the DB: apply the system theme, render immediately, then apply the saved theme when it loads (store the last mode in `localStorage` too and apply it synchronously first, inside try/catch).
- [x] 13. **Dead code**: remove `PlaceholderScreen` and unused `common` keys (`comingSoon*`) if nothing uses them; remove unused shadcn leftovers; no unused exports in `src/ui/components/index.ts` that nothing imports is fine to keep.
